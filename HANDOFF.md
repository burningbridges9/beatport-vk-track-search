# HANDOFF — поиск треков в VK с чужого сайта

Дата: 2026-10-18. Репозиторий: `beatport-vk-track-search`, версия **1.2.0**, тесты **100/100**.
Соседний репозиторий: `vk-tracklist-track-search` (там трек берётся из текста поста VK).

> Этот файл можно приложить к новой сессии как контекст: в нём постановка задачи,
> что переносится без изменений, что придётся написать для нового сайта, методика
> снятия разметки, грабли и чек-лист приёмки.

---

## 1. Задача и что получилось

В Beatport (и в любой другой каталог музыки) нужно встроить кнопку рядом с треком:
нажал — открылся поиск этого трека в аудио VK, с уже подставленным запросом.

Схема одинаковая для любого источника:

```text
[сайт-источник]  --кнопка-->  https://vk.ru/audios<ID>?q=<запрос>
        |                              ^
        |  DOM: название, артисты      |
        +---- common.js: шаблон запроса, двойное кодирование,
              vk.js: ID владельца аудио и достройка потерянного q
```

Что уже сделано (можно смотреть как на эталон):

| Возможность | Где живёт |
|---|---|
| Адрес поиска и кодирование | `common.js` — `encodeQuery`, `buildSearchUrl` |
| Шаблон запроса | `common.js` — `renderQuery` |
| ID владельца аудио, отложенный запрос | `vk.js` + `chrome.storage` |
| Кнопка и её поведение | `content.css`, `content.js` |
| Настройки | `options.html/css/js` |
| Тесты на jsdom | `test/run-tests.mjs`, `test/fixture*.html` |
| Сборка | `tools/build.ps1` |

## 2. Что НЕ зависит от сайта и переносится как есть

### 2.1 Адрес поиска

```text
https://vk.ru/audios<ID>?q=<дважды URL-encoded запрос>
```

```js
function encodeQuery(query, encoding) {
  var once = encodeURIComponent(query);
  // VK декодирует параметр ещё раз: в адресах сайта пробел выглядит как %2520
  return encoding === 'single' ? once : encodeURIComponent(once);
}

function buildSearchUrl(query, ownerId, encoding) {
  var id = /^\d{1,20}$/.test(String(ownerId || '')) ? String(ownerId) : '';
  return 'https://vk.ru/audios' + id + '?q=' + encodeQuery(query, encoding);
}
```

Проверка: `Ink, Mesto - Freak` → `Ink%252C%2520Mesto%2520-%2520Freak`.
Если у пользователя в строке поиска VK видно `%20` — в настройках переключается на
одинарное кодирование (`queryEncoding: 'single'`).

Адрес всегда абсолютный на `https://vk.ru` — кнопка стоит на чужом домене, поэтому
`location.origin` брать нельзя.

### 2.2 ID владельца аудио

VK ищет внутри «музыки» конкретного владельца, поэтому в адресе нужен `<ID>`.
Порядок:

1. `audioOwnerId` из настроек — если пользователь вписал вручную;
2. `detectedAudioOwnerId` из `chrome.storage.local` — ID, выученный на VK;
3. пусто → ссылка `https://vk.ru/audios?q=…`.

Учит ID скрипт `vk.js` (content script на `vk.ru`/`vk.com`): как только в адресе
появляется `/audios<ID>`, ID сохраняется. Ссылки со страницы-источника для этого
не годятся — там можно попасть на чужую музыку.

### 2.3 Отложенный запрос (первый клик работает всегда)

Если ID ещё неизвестен, перед переходом запрос кладётся в
`chrome.storage.local.pendingAudioSearch = { query, ts }`. Вкладка VK, открывшись:

- `q` в адресе уже есть — ничего не делает;
- адрес стал `/audios<ID>` без `q` — переходит на `/audios<ID>?q=…`;
- адрес остался `/audios` — ждёт SPA-перехода и повторяет проверку;
- запись живёт 2 минуты и стирается при первом использовании.

**Важно:** писать pending нужно на `pointerdown`/`mousedown`/`auxclick`, а не только
на `click` — новая вкладка может начать загружаться раньше, чем завершится
асинхронная запись в storage. В текущем коде так и сделано (`onPressStart`).

### 2.4 Кнопка

Кнопка — это `<a href="…">`, а не `<button>`: тогда бесплатно работают Ctrl+клик,
средний клик, «открыть в новой вкладке/окне» и контекстное меню браузера.

Обязательные мелочи:

- `event.stopPropagation()` на `click`, `mousedown`, `pointerdown`, `mouseup`,
  `auxclick` — иначе SPA-сайт уведёт на свою страницу трека по клику на строку;
- `position: relative; z-index: 2` — если у сайта есть абсолютный оверлей-ссылка
  на всю строку, иначе кнопка окажется под ним;
- `display: inline-flex`, `flex: none`, `user-select: none`, `text-decoration: none`
  и `!important` на ключевых свойствах — рядом чужие стили;
- `title` и `aria-label` содержат **точный** запрос: `Найти «…» в аудио VK` —
  пользователь видит, что уйдёт в VK;
- перед кликом адрес пересчитывается: ID мог появиться уже после отрисовки;
- `openInNewTab = false` → не ставим `target`, отдаём переход браузеру.

### 2.5 Шаблон запроса

`common.js → renderQuery(info, settings)`, токены:

| Токен | Значение |
|---|---|
| `{artists}` | все артисты через запятую |
| `{artist}` | то же (синоним; оставлен, чтобы старые шаблоны заработали правильно) |
| `{mainArtist}` | только первый артист |
| `{title}` | название трека |
| `{mix}` | микс: `Extended Mix`, `Original Mix`, `Club Mix` |
| `{label}` | лейбл |

По умолчанию `{artists} - {title}`. Почему все артисты: в VK трек обычно подписан
так же, как на Beatport, — `Bryan Kearney, John O’Callaghan, Key4050 - Stay In Your Lane`.

Нормализация ответа (делать обязательно, иначе получаются уродливые запросы):

- микса нет → убираем `({mix})` целиком, а не оставляем `()`;
- схлопываем пробелы, убираем пустые `()`, висячие запятые;
- срезаем ведущие и хвостовые разделители (` - `, `, `), если артиста/названия нет;
- шаблон без `{title}` считается негодным → значение по умолчанию.

### 2.6 Настройки

`chrome.storage.sync`: `enabled`, `queryTemplate`, `openInNewTab`, `queryEncoding`,
`audioOwnerId`. `chrome.storage.local`: `detectedAudioOwnerId`, `pendingAudioSearch`.

Страница настроек повторяется для любого сайта: переключатели, шаблон с пресетами
и токенами, предпросмотр «запрос + готовый URL» на живом примере, ID владельца
аудио и строка «определён автоматически: …», сброс, версия.

## 3. Что придётся написать для нового сайта

Только **один файл** — content script источника. Всё остальное копируется.

### 3.1 Контракт, который завязан на content script

| Что | Значение |
|---|---|
| Класс кнопки | `a.bp2vk-btn` (префикс — чтобы не столкнуться со стилями сайта) |
| Атрибуты | `data-bp2vk-btn`, `data-bp2vk-query`, `data-bp2vk-key` |
| Готовность страницы | `<html data-bp2vk-scans="N" class="bp2vk-ready">` |
| Выключено | `<html class="bp2vk-disabled">` — CSS прячет кнопки |
| Поиск всех кнопок | `document.querySelectorAll('a.bp2vk-btn')` |

`data-bp2vk-scans` — счётчик сканирований. Он нужен тестам, чтобы ждать
«страница пересканирована», а не «прошло 400 мс» (см. п. 5.8).

### 3.2 Скелет content script для нового сайта

Ниже — только то, что меняется от сайта к сайту. Жизненный цикл (наблюдатель,
перерисовка, настройки, prune) одинаковый и копируется из `content.js` этого
репозитория.

```js
// ---- SITE: где на странице лежит ровно один трек (или релиз) -------------
var HOST_SELECTORS = [
  '[data-testid="track-row"]',            // таблица треков
  '[class*="TrackCard_wrapper"]'          // карточка
];
var HOST_SELECTOR = HOST_SELECTORS.join(',');

// ---- SITE: ссылка на сущность и узел с названием -------------------------
var TRACK_LINK = 'a[href*="/track/"]';    // *=, а не ^= — бывают /es/track/…
var RELEASE_LINK = 'a[href*="/release/"]';
var NAME_SELECTOR = '[class*="Title"], [class*="ReleaseName"], [class*="releaseName"]';
var ARTISTS_BOX = '[class*="ArtistNames"], [class*="Artists_"]';
var ARTIST_LINK = 'a[href*="/artist/"]';

// Самый вложенный кандидат: селектор по подстроке класса часто цепляет обёртку
// (ReleaseCard_releaseNameWrapper) вместо самого названия.
function findNameNode(host) {
  var nodes = qsa(NAME_SELECTOR, host);
  for (var i = 0; i < nodes.length; i++) {
    var containsAnother = false;
    for (var j = 0; j < nodes.length; j++) {
      if (i !== j && nodes[i].contains(nodes[j])) { containsAnother = true; break; }
    }
    if (!containsAnother) return nodes[i];
  }
  return null;
}

// Название = текст узла, микс = текст вложенного <span>.
function splitName(node) { /* см. content.js */ }

function readInfo(host, kind) {
  var anchor = host.querySelector(TRACK_LINK) || host.querySelector(RELEASE_LINK);
  var nameNode = findNameNode(host);
  var parsed = splitName(nameNode);
  var title = parsed.title || normalizeText(anchor && anchor.getAttribute('title'));
  if (!title) return null;                       // не трек — молча пропускаем

  // Ссылка ИМЕННО названия: у карточки первая ссылка в контейнере — обложка.
  var nameAnchor = (nameNode && nameNode.closest('a')) || anchor;

  return {
    title: title,
    mix: parsed.mix,
    artists: readArtists(host),                  // все a[href*="/artist/"] в host
    label: labelOf(host),
    entityId: parseEntityId(nameAnchor && nameAnchor.getAttribute('href')),
    nameAnchor: nameAnchor,
    kind: kind                                  // 'row' | 'header' | 'card' | 'hero'
  };
}

// ---- SITE: куда физически вставить кнопку -------------------------------
function insertionPoint(info) {
  // Если у блока есть готовый ряд иконок (play/queue/…) — встаём в него.
  // Иначе — сразу после ссылки с названием.
  var anchor = info.nameAnchor;
  if (!anchor || !anchor.parentElement) return null;
  return { parent: anchor.parentElement, before: anchor.nextSibling };
}
```

Дальше — общий код: `createButton`, `syncButton`, `scan`, `pruneButtons`,
`MutationObserver`, проверка `location` раз в ~800 мс, реакция на
`chrome.storage.onChanged`.

### 3.3 Пять вопросов, на которые нужны ответы до кода

1. **Где появляется отдельный трек?** Контейнер, внутри которого ровно один трек
   или один релиз (не вся секция).
2. **Где название, а где микс?** Часто это один узел: текст — название, вложенный
   `<span>` — микс. Иногда микс уже внутри названия в скобках.
3. **Где артисты?** Ссылки `a[href*="/artist/"]` внутри контейнера. Если ссылок нет —
   придётся брать текст из узла и чистить.
4. **Куда вставить кнопку?** Так, чтобы не сломать layout и не попасть в зону,
   которая появляется только при наведении.
5. **Как сайт обновляет DOM?** SSR + гидратация, клиентский роутинг,
   виртуализация, бесконечная прокрутка — от этого зависит только частота сканов.

## 4. Методика снятия разметки (переносится на любой сайт)

Порядок, который сработал; каждый шаг дешевле предыдущего.

1. **Скачать реальный HTML.** `urllib`/`curl` с браузерным `User-Agent`,
   `Accept-Language` и `Accept-Encoding: gzip`. Без UA многие сайты отдают 403
   (у Beatport — Cloudflare).
2. **Понять, SSR это или клиент.** Ищем данные в `<script id="__NEXT_DATA__">`
   (Next.js) или аналогичном JSON; сравниваем с DOM. В Beatport:
   - таблицы (топ-100, лейбл, артист) — SSR, строки в HTML есть;
   - топ жанра — SSR, строки-списки есть;
   - **треклист релиза — клиентский**: в HTML строк нет, только JSON релиза.
     Зато та же компонента строки встретилась на странице жанра — оттуда и сняли.
3. **Найти нужные компоненты.** Гистограмма классов/`data-testid` по документу:
   `Counter` по `class` и `data-*` сразу показывает, сколько чего на странице
   (у нас: 190 карточек релизов, 7 hero, 29 строк, 100 строк таблицы).
4. **Проверить селекторы скриптом по сохранённому HTML, а не глазами.** lxml/python:
   для каждого контейнера вывести «название / первый артист / куда встанет кнопка».
   Это отлавливает 80% ошибок до браузера.
5. **Финальная проверка: прогнать настоящий content script в jsdom на реальном
   HTML страницы** (не на фикстуре). Мы так поймали, что кнопки появляются на всех
   100 строках, а запрос у трека с четырьмя артистами выглядит как
   `Majestic, Layton Giordani, Jungle 70, HILLS (US) - Bassline`.
6. **Headless Chrome для сайтов с Cloudflare бесполезен** — приходит страница
   «Один момент…», а не магазин. Локальные страницы (свои настройки) им снимать
   можно.

## 5. Грабли (симптом → причина → решение)

**5.1. Запрос содержит только одного артиста.**
Причина: токен `{artist}` исторически означал «первый».
Решение: `{artist}` = все артисты (синоним `{artists}`), `{mainArtist}` = первый,
шаблон по умолчанию `{artists} - {title}`. Старые сохранённые шаблоны при этом
начинают работать правильно без правок пользователя.

**5.2. Кнопка появляется не там (у обложки вместо названия).**
Причина: селектор по подстроке класса цепляет обёртку
(`ReleaseCard_releaseNameWrapper` содержит `releaseName`), а `closest('a')` у обёртки
не находится, и в дело идёт первая ссылка контейнера — обложка.
Решение: `findNameNode` — берём **самый вложенный** кандидат, затем `closest('a')`.

**5.3. Название и микс склеены.** Симптом: `Freak Extended Mix` без скобок.
Причина: в разметке это один узел: текст `Freak`, вложенный `<span>` `Extended Mix`.
Решение: `splitName` обходит только прямых детей: текстовые узлы → название,
`<span>` → микс.

**5.4. Локализованные версии не работают.** Симптом: на `/es/…` кнопок нет.
Причина: ссылки с префиксом — `/es/track/mumble/30175842`.
Решение: искать по вхождению (`a[href*="/track/"]`), номер сущности парсить
регуляркой из любого варианта (`/\/track\/(?:[^\/?#]+\/)?(\d+)/`).

**5.5. Кнопок нет до перезагрузки или после перехода.** Симптом: зашли на релиз —
пусто, `F5` — появились.
Причина: список рендерится после гидратации; SPA меняет адрес без перезагрузки.
Решение: `MutationObserver` на `document.documentElement` (childList, subtree) с
дебаунсом ~200 мс + проверка `location.pathname + search` раз в ~800 мс.
Сканировать при инициализации, а не по `DOMContentLoaded`.

**5.6. Дубли кнопок после перерисовки.**
Причина: новая кнопка добавляется поверх старой; вложенные контейнеры дают две
кнопки на один трек.
Решение: на каждый хост ищем уже существующую `a.bp2vk-btn` и **обновляем** её
(`syncButton`) вместо создания; `pruneButtons` удаляет кнопки, чей хост больше не
считается треком; при обходе хостов пропускаем вложенные контейнеры.

**5.7. Кнопка в зоне, которая видна только при наведении.**
Причина: у списков и таблиц кнопки play/queue появляются на hover.
Решение: выбирать всегда видимый узел (строка названия) либо готовый ряд действий,
если он виден постоянно. У Beatport: строки — после названия; шапка трека и
hero-релиз — в ряд play/queue/playlist.

**5.8. Тесты мигают.** Симптом: локально зелено, в `build.ps1 -Test` — красное.
Причина: `await sleep(400)` при дебаунсе 200 мс и загруженной машине.
Решение: сканирование пишет `<html data-bp2vk-scans="N">`, тест ждёт
`N > предыдущего` (`afterMutation` в `test/run-tests.mjs`).

**5.9. Любая запись файлов из PowerShell 5.1 ломает JSON.**
Причина: `Set-Content -Encoding UTF8` добавляет BOM, `JSON.parse` падает на `﻿{`.
Решение: `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`
или править файлы инструментом, а не `Set-Content`.

**5.10. Клик по кнопке уводит на страницу трека сайта.**
Причина: у строки свой обработчик клика (оверлей-ссылка).
Решение: `stopPropagation` на пяти событиях + `z-index` (см. п. 2.4).

**5.11. Расширение мешает выделять текст и ломает вёрстку.**
Решение: `user-select: none`, `flex: none`, фиксированные 16–18 px,
`!important` только на своих свойствах.

## 6. Чек-лист нового сайта

1. Скопировать каркас: `common.js`, `vk.js`, `background.js`, `content.css`,
   `options.html/css/js`, `tools/`, `test/run-tests.mjs`, `.gitignore`.

4. Снять 3–5 реальных фрагментов разметки в `test/fixture-<site>.html`

5. Переписать ожидания в `run-tests.mjs`: счётчики по регионам, точные запросы,
   позиция кнопки, локализованный вариант.
6. Прогнать настоящий content script в jsdom **на реальном HTML** страницы.
7. Заменить пример трека в предпросмотре настроек (`options.js`, `SAMPLE`).
8. Обновить README: раздел «Где ищутся треки» под новый сайт, версия, счётчик тестов.
9. `powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Test`.
10. Живой браузер: `chrome://extensions` → «Обновить» → `F5` на странице.

## 7. Критерии приёмки

- кнопка есть на каждом типе страницы, где встречается трек/релиз;
- в запросе все артисты, микс — по шаблону, лишних скобок и разделителей нет;
- кнопка стоит у названия/в ряду действий, не ломая layout, работает Ctrl+клик
  и средний клик;
- клик не уводит на страницу сайта;
- после перерисовки, добавления и удаления строк кнопок ровно столько, сколько
  нужно (нет дублей и «сирот»);
- SPA-переход не плодит кнопки;
- первый поиск работает даже без выученного ID владельца аудио;
- тесты зелёные, `dist/*.zip` собирается, README и скриншот настроек актуальны.

## 8. Ограничения подхода

- Всё держится на разметке сайта: классы и `data-*` меняются — селекторы ломаются.
  Поэтому имена селекторов собраны в одном месте, а тесты идут на фикстуре.
- Клиентский рендер даёт короткое окно, когда кнопок ещё нет; это нормально.
- Карточка релиза не содержит треклиста: для EP запрос пойдёт по названию релиза,
  и в VK он может не найтись. Для синглов совпадает.
- Кнопка не должна попадать в зоны, видимые только на hover, иначе её не найдут.
- Без выученного ID первый клик идёт через редирект VK и отложенный запрос;
  если VK поменяет поведение — смотреть `handlePendingSearch` в `vk.js`.
- Апострофы и типографика: `John O’Callaghan` уходит как есть. Если VK не находит
  трек, а с ASCII `'` находит — нужна нормализация в `renderQuery`.

## 9. Если сайт что-то поменял

1. Обновить вкладку и проверить, что расширение включено.
2. В DevTools: у `<html>` есть `data-bp2vk-scans`? Нет — скрипт не запускался.
3. Есть ли контейнеры (`HOST_SELECTORS`) и ссылка на сущность внутри?
4. Есть ли узел с названием (`NAME_SELECTOR`) — и какой из кандидатов самый вложенный?
5. Посмотреть, куда попадает кнопка: `a.bp2vk-btn` → `parentElement`.
6. Поправить селекторы, обновить фикстуру и ожидания тестов, прогнать
   `node test/run-tests.mjs`.

Ключевые функции: `content.js` — `hosts`, `readInfo`, `findNameNode`, `splitName`,
`readArtists`, `readInfo.entityId`, `insertionPoint`, `scan`, `pruneButtons`;
`common.js` — `renderQuery`, `encodeQuery`, `buildSearchUrl`; `vk.js` —
`refresh`, `resolvePending`.
